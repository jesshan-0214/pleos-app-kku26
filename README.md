# 라이드메이트 (RideMate)

> 함께 탄 사람을 중심으로 여정을 계획하고, 이동 시간을 가족 모두가 즐길 수 있는 경험으로 바꾸는 차량용 동승자 플랫폼

**RideMate**는 현대자동차그룹 차량용 앱 개발 공모전(Pleos Playground)을 위해 기획한 프로젝트입니다.
운전자뿐 아니라 함께 탑승한 **2명 이상의 가족 구성원**도 여행에 참여할 수 있도록 돕습니다. 어린이·고령자 등 동승자의 특성을 고려한 여정 안내, 퀴즈, 투표, 도착 알림을 하나의 경험으로 연결합니다.

> **안내:** 아래 기능과 기술 구성은 프로젝트의 **설계 범위**를 설명하며, 모든 기능의 구현 완료를 의미하지는 않습니다.

## 주요 기능

사용 흐름은 **출발 → 이동 중 → 경유지 → 도착 → 여행 후**로 구성됩니다.

### 출발

| 기능 | 설명 |
| --- | --- |
| 탑승자 프로필 | 이름, 나이대, 좌석, 희망 휴식 간격을 저장하고 다음 여행에서 다시 사용합니다. |
| 탑승자 맞춤 일정 | 탑승자 구성과 휴식·식사 시간을 고려해 경로 주변 관광지와 휴게소를 포함한 일정을 제안합니다. |
| 목적지·경유지 설정 | 목적지를 지정하고 선택한 경유지를 내비게이션 경로에 반영합니다. |

### 이동 중

| 기능 | 설명 |
| --- | --- |
| 남은 시간 비유 안내 | 남은 시간을 어린이가 이해하기 쉬운 '노래 몇 곡 분량' 등의 표현으로 안내합니다. |
| 지역 퀴즈 | 지나가는 지역을 소재로 퀴즈를 제공하고 음성 또는 동승자 휴대폰으로 답변을 받습니다. |
| 운전자에게 박수 보내기 | 동승자가 휴대폰에서 보낸 응원·박수를 차량 음성으로 전달합니다. 차속 변화에 따른 운전 상황도 활용하도록 설계합니다. |

### 경유지

| 기능 | 설명 |
| --- | --- |
| 경유지 QR 투표 | 동승자가 휴대폰으로 경유지 후보에 투표하고, 추가 소요 시간과 결과를 확인합니다. |
| 메뉴 QR 투표 | 식사 메뉴 후보를 함께 정하고 결과를 공유합니다. |
| 휴식 제안 | 설정한 휴식 간격과 현재 위치를 고려해 가까운 휴게소를 미리 제안합니다. |
| 주변 식당 검색 | 선택한 메뉴에 맞는 주변 식당을 찾아 경유지 후보로 제시합니다. |

### 도착

| 기능 | 설명 |
| --- | --- |
| 지역 배지 | 방문한 지역의 배지를 획득하고 도감에 기록합니다. |
| 구성원별 체크리스트 | 출발 전에 등록한 물품을 탑승자별로 분류해 도착 시 안내합니다. |
| 문 열림 연동 안내 | 하차하는 좌석을 확인할 수 있는 환경에서 해당 구성원의 물품을 안내합니다. |
| 여정 카드 | 경로, 퀴즈, 배지를 요약한 카드를 동승자 휴대폰에 전달합니다. |

### 여행 후

| 기능 | 설명 |
| --- | --- |
| 이동 경로 기록·다시보기 | 주행 중 기록한 이동 경로를 지도에서 확인합니다. |
| 경로 위 사진 | 휴대폰에서 업로드한 사진의 위치·시간 정보를 이용해 이동 경로와 함께 표시합니다. |

### 안전을 고려한 사용 방식

- 주행 중 차량 화면의 터치 조작을 제한하고, 필요한 참여는 **음성**이나 **동승자 휴대폰**으로 진행하도록 설계합니다.
- 운전자와 동승자의 역할을 분리해, 운전자가 화면 조작에 집중하지 않도록 합니다.
- 차량 상태와 도착 이벤트를 활용하는 기능은 실제 SDK 지원 범위와 에뮬레이터 동작을 확인하면서 적용합니다.

## 시스템 구성

```text
┌────────────────────────┐       ┌──────────────────────┐       ┌────────────────────────┐
│ 차량용 앱              │       │ Firebase             │       │ 동승자 휴대폰 웹       │
│ Kotlin · Compose       │◀─────▶│ Realtime Database    │◀─────▶│ HTML / JavaScript      │
│ Pleos Connect SDK      │       │ Storage · Hosting    │       │ QR 접속 · 앱 설치 불필요│
└────────────────────────┘       └──────────────────────┘       └────────────────────────┘
```

| 구성 요소 | 역할 |
| --- | --- |
| **차량용 앱** | 차량 화면, 내비게이션 연동, 위치 및 차량 상태 조회, 음성 입출력 |
| **동승자 휴대폰 웹** | QR 접속 후 투표, 퀴즈 답변, 체크리스트 확인, 응원, 사진 업로드 |
| **Firebase** | 차량용 앱과 휴대폰 웹 사이의 실시간 데이터 동기화 및 콘텐츠 저장 |

차량용 앱은 **Screen → ViewModel → SDK별 Client** 구조로 구분해, 화면 코드와 SDK 호출 로직을 분리하는 것을 기준으로 합니다.

## 기술 스택 및 SDK/API

| 분류 | 기술 | 사용 목적 |
| --- | --- | --- |
| 차량 앱 | Kotlin, Jetpack Compose | Pleos Connect 기반 UI와 앱 로직 |
| 차량·내비 | Pleos Connect SDK의 NaviHelper, FusedLocation, Vehicle API | 목적지·경유지, 현재 위치, 차량·도착 상태 |
| 음성·AI | TextToSpeech, SpeechToText, LLM(Gleo AI 연동 검토) | 음성 안내·답변, 퀴즈·텍스트 생성 |
| 차량 속도 | AAOS `CarPropertyManager` | 주행 상태 확인과 터치 제한 판단 |
| 동승자 웹 | HTML, JavaScript | 앱 설치 없는 휴대폰 참여 화면 |
| 실시간 연결 | Firebase Realtime Database, Storage, Hosting | 투표·응답 동기화, 사진 보관, 웹 배포 |
| 지역·장소 정보 | 한국관광공사 TourAPI, 카카오 로컬 API | 관광지·지역 정보·주변 식당 조회 |
| 지도·이미지 | 카카오맵 SDK, exifr | 여행 경로 시각화 및 사진 메타데이터 처리 |
| 로컬 저장 | Room | 탑승자 프로필, 배지, 체크리스트 및 경로 기록 |
| QR | ZXing | 동승자 참여 링크의 QR 코드 표시 |

**주요 내비게이션 연동 항목:** `requestRoute`, `addWaypoint`, `getRouteStateInfo`, `onDestinationArrived`, `onWayPointArrived`를 활용하도록 설계했습니다. 구체적인 호출 및 사용 가능 범위는 SDK 검증 결과에 따라 조정될 수 있습니다.

## 저장소 구조

다음은 프로젝트의 **설계 기준 디렉터리 구조**입니다. 실제 폴더 구성은 구현에 따라 달라질 수 있습니다.

```text
pleos-app-kku26/
├── app/                      # 차량용 Android 앱
│   └── src/main/java/com/pleos/familyjourney/
│       ├── core/             # SDK Client, AI, 네트워크, Firebase, Room 등 공통 코드
│       └── feature/          # home, departure, quest, vote, arrival, extras 등 기능별 코드
├── web/                      # QR로 접속하는 동승자 웹
├── firebase/                 # Firebase 보안 규칙
└── docs/                     # 설계 및 개발 관련 문서
```

- 기능별 `feature` 코드 간 직접 의존을 최소화하고, 공통으로 쓰는 로직은 `core`에 배치합니다.
- API 키 및 서비스 설정 파일은 공개 저장소에 노출하지 않는 것을 원칙으로 합니다.
